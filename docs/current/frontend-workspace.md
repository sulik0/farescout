# 前端研究工作台：结果、依据与验证记录

更新：2026-10-03。本次只调整本机前端及相关会话状态处理，继续使用现有 Session、Evidence、研究事件和 SSE。没有改变研究算法，也没有增加外部来源。

## 打开后先看到什么

桌面页面分为三栏。左侧用来输入需求、继续提问、修改条件和选择历史记录。中央先展示航线机会，每张卡片直接写明目的地、具体日期、价格、含税情况和查询时间，并给出发现这条线索的理由。右侧展示 Research Trace（研究轨迹）和结论依据。

有历史记录时，页面默认回放最近一项研究，不会自动发起新查询。研究完成后，航线卡片仍在中央最上方；条件解释放在左侧折叠区，调用量和耗时放在结果下方的折叠区。窄屏中，已有结果排在输入区之前，页头可以跳到继续提问的位置。没有结果时，页面如实展示读取中、部分完成或来源受阻，不用示例报价填满卡片。

## 用户怎样核对一条结论

点击航线卡片的“追溯依据”，右侧会选中这条航线，依次展示：

1. 为什么从社区材料里选出这条航线。
2. 引用的帖子、原文摘录、社区晒价、发布时间和读取时间。展开帖子可以阅读正文与评论，也可以打开原链接。
3. 日期窗口、发出过精确请求的日期、失败日期和最终复验日期。范围查询返回的日期单列，不算作逐日验价。
4. 各票价来源在各日期查到的报价、含税情况、航段、查询时间、行李说明，以及来源之间的差异和未确认部分。

“查看这条航线的完整研究轨迹”会切回右侧轨迹，保留航线范围。用户可以继续筛选社区、日期、验价或失败与冲突，也可以清除航线范围查看整个研究。后续轮次沿用早期证据时，轨迹会带回相关原文事件并标明来自哪一轮；不会把早期报价带入本轮验价。

社区晒价不进入卡片的当前报价。卡片优先使用有含税口径的报价；若只有税费未知的报价，会明确标注。日期直接取自这条报价的请求，避免把一个日期的价格放到另一个日期下。历史回放保留原查询时间，不能理解为此刻仍能买到。多个税费口径不同的来源分别展示，不合成“最低到最高”的价格区间。

## 修复了哪些交互问题

- 切换历史记录后，旧请求不能覆盖当前会话。同一会话的多个刷新请求也只接收最新一次结果。
- 新建研究会清空旧报告链接、选中轮次、卡片、追溯范围和状态，不会误打开上一次的报告。
- 正在修改的日期和行程不会被实时快照覆盖；往返停留天数检查为 1～30 的整数。
- 空白需求在前端就会被拦截，不会先创建一个无效会话编号。
- 查看历史记录时仍遵守全局研究任务限制。可以阅读其他结果，但不会再启动第二个任务；后台任务结束后按钮会恢复。
- SSE 断开时保留自动重连，并尝试读取保存的快照；旧连接的回调不能修改新会话。持续到来的事件采用节流刷新，避免一直重置计时器而不更新页面。
- 服务端异常只返回给发生异常的会话，避免在另一项历史研究中显示无关错误。

## 实现放在哪里

| 文件 | 做什么 |
|---|---|
| `src/farescout/ui.html` | 三栏结构、输入表单、条件编辑、结果和右侧面板 |
| `src/farescout/ui.css` | 桌面独立滚动区域、航线卡片和窄屏布局 |
| `src/farescout/ui.mjs` | 读取会话、实时更新、历史回放、航线追溯和表单交互 |
| `src/farescout/ui-state.mjs` | 与 DOM 无关的会话状态、报价选择、日期覆盖和事件关联规则 |
| `src/farescout/web.py` | 显式提供前端资源，并按会话返回错误；仍只允许本机同源访问 |
| `tests/frontend.test.mjs` | 验证请求竞争、报告轮次、报价口径、日期覆盖和跨轮证据关联 |

仍使用原生 HTML、CSS 和 JavaScript，不引入前端框架、构建工具或新数据库。前端资源随 Python 包一起安装。新增资源地址有固定白名单，不开放任意文件读取。
