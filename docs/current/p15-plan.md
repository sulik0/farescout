# P1.5：让研究更稳定、更快

继续使用现有 Pydantic AI、socai、FlyAI、SerpAPI、Session 和 Evidence。先记录两次原版冷启动，再在同一输入下重复运行修改版。每次都新建会话；失败也计入结果，不复用历史帖子冒充新研究。

- 社区读取：用 socai 读取搜索结果第一页，再逐篇读取选中的正文，不为凑卡片数量滚动。卡片不能成为证据；单篇失败不丢弃其他正文。登录、验证码和浏览器连接失败停止该来源；逐篇模式无正文时只回退一次完整扫描，完整扫描模式最多用短查询重试一次，再尝试原有备用来源。
- 耗时：分别记录模型、社区搜索、正文读取、日期探索和验价耗时。区分阶段实际用时和并发请求耗时之和；给候选提取和验价预留最多120秒，避免社区失败耗完整轮预算。
- 日期：限制调用预算；复用本轮同条件的新鲜报价，保留原始抓取时间。比较 FlyAI range、Google Travel Explore 和 Flights Deals 的真实响应；这些只能提供待验日期，不能证明全月最低。
- 证据：除同文转载外，识别航司、活动日期和官方链接相同的促销。只在有明确共同线索时合并计数，不把相同航司或目的地当作同一来源。

验收输入为“香港 11 月飞日本哪里便宜？”。记录每轮状态、失败原因、实际日期覆盖、调用次数、总耗时、各阶段耗时、有效正文数和可验证机会数。保持 P1 的完成标准；浏览器未连接或来源失败时如实报告。

当前最大风险是socai在小红书搜索页和帖子之间切换失败、无法取得正文；Chrome连接已恢复并可复用，但登录和授权状态仍需检查。另有社区页面变化和外部API可用性的风险。不迁移 Runtime，不引入 Multi-Agent，不新增社区平台或 OTA。
