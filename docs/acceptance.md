# POC Definition of Done 验收

唯一产品基准：[需求原文第 33 节](product-requirements.md)。**本机独立命令行版本已真实完成一次“社区发现 → 自主调查 → 当前验价 → 两类来源与双票价渠道交叉核查 → 可解释结论”。** 15 项 MUST 在本次样本内均为 PASS。完整运行后再次单独执行 socai 搜索，之后仍成功读到 5 篇帖子正文和 4 条评论；不过，这不足以证明系统连续多天都稳定、任意日期的供应覆盖，或机会质量始终优于人工研究。

## 最新真实运行

2026-09-30（Asia/Shanghai），输入“帮我研究深圳香港最近有什么便宜国际机票。”；完整记录为 [独立会话 JSON](../reports/standalone-session.json)，易读版为 [首轮报告](../reports/05-standalone-discovery.md)。全程只读，未使用宿主浏览器回执。

- socai v0.6.1 连接已登录 Chrome，先后搜索“深圳香港出发国际机票”和“深圳香港飞国外便宜机票”，读取 7 篇不同正文；模型根据已经读到的帖子提出“香港快运 亚庇 10月 单程 特价 日期”并实际执行，累计读到 12 篇帖子正文。
- 模型抽取的每条候选都必须附上证据编号和帖子正文或评论中的原文摘录；程序核对城市、机场、日期和价格原文后，选出 5 条路线。FlyAI 与 SerpAPI Google Flights 各自按 **2026-10-14、1 成人、经济舱、单程、CNY** 查询；程序还逐一核对返回结果中的机场、日期、行程类型和航段。
- 两个票价渠道在亚庇、槟城、河内、名古屋均成功。巴厘岛的 FlyAI 返回 `API_ERROR`，SerpAPI 继续得到报价。这是一次真实来源失败后的继续任务案例。

| 社区发现方向 | FlyAI 票价，税费未知 | Google Flights 含税总价 | 当前判断 |
|---|---:|---:|---|
| 香港 → 亚庇 BKI | CNY 829 | CNY 796 | 两渠道均有结果；口径不同，不能直接相减 |
| 香港 → 槟城 PEN | CNY 730 | CNY 763 | 两渠道均有结果；口径不同，不能直接相减 |
| 香港 → 巴厘岛 DPS | 失败 | CNY 1502 | 当前只有一个成功的票价渠道 |
| 香港 → 河内 HAN | CNY 627 | CNY 662 | 两渠道均有结果；口径不同，不能直接相减 |
| 香港 → 名古屋 NGO | CNY 914 | CNY 952 | 两渠道均有结果；口径不同，不能直接相减 |

这些报价的记录时间约为 2026-09-30 16:59（Asia/Shanghai）。这些是**当时针对抽查日期取得的报价**，不是可售承诺、整个日期窗口的最低价，也不能与社区里不同日期、行李、退税或币种的晒价直接比较。FlyAI 的 `ticketPrice` 未给可靠税费口径，Google Flights 的 `price` 为含税报价；报告并列呈现，不伪造一个可比价差。

首轮从启动到报告完成用时 **3 分 17.6 秒**（`started_at` 至 `finished_at`），包含真实社区和票价调用。这次研究在半小时内完成，但没有与同条件的人工作业做盲测，也不能据此推断每次研究都能在相同时间内完成。

## 15 项 MUST

| 项目 | 结果 | 本次真实证据与边界 |
|---|---|---|
| MUST 1 模糊输入直接研究 | PASS | 未要求先填写目的地、日期等完整参数；默认条件在报告明示 |
| MUST 2 多个社区搜索 | PASS | 先做 2 次范围较宽的搜索，再根据已读帖子提出并实际执行 1 次新查询 |
| MUST 3 阅读若干正文 | PASS | socai 返回 12 篇可核对正文，含评论；搜索卡片未计数 |
| MUST 4 抽取有效信息 | PASS | 发现目的地、香港快运等航司、社区晒价、促销与限制信息，并附有原文引用 |
| MUST 5 自主 Query Expansion | PASS | 模型根据已读帖子中的“香港快运”“亚庇”提出新查询，程序检查依据并真正调用 socai |
| MUST 6 多信号筛选少量候选 | PASS | 12 篇证据中筛到 5 条有出处的航线；目前不是全网大样本覆盖试验 |
| MUST 7 候选实时验价 | PASS | 5 条均有当前渠道报价，含实际航段、具体日期和查询时间 |
| MUST 8 两种性质的信息源 | PASS | 小红书社区 + FlyAI / 飞猪 + Google Flights / SerpAPI；后两者是不同票价渠道 |
| MUST 9 社区与当前价格区分 | PASS | 分栏写社区原文和当前报价，注明单程/往返、币种、税费、行李口径 |
| MUST 10 价格冲突不伪造单价 | PASS | 两票价渠道数值不同但税费口径不同，分别列示；同口径冲突分组逻辑由隔离测试验证，不声称已观察到可同口径直接比较的冲突 |
| MUST 11 多轮上下文延续 | PASS | 在独立会话继续“日本呢 → 11 月呢 → 不要红眼”；保留 SZX/HKG 和 12 篇证据，重新筛选及验价 |
| MUST 12 来源失败时继续 | PASS | 巴厘岛 FlyAI 失败而 SerpAPI 成功；后续日期也有多条 FlyAI 失败但 SerpAPI 继续成功 |
| MUST 13 3～5 个机会 | PASS | 首轮 5 条、追问日本 3 条、11 月和不要红眼各 4 条有当前价格的调查方向；不是 API 数据转储 |
| MUST 14 可解释结论 | PASS | 每项写发现原文、报价性质、冲突口径、关注理由和限制；无历史基线时不声称已证明“超低价” |
| MUST 15 无交易行为 | PASS | 仅小红书搜索/读取及只读航班 API，未访问预订 `jumpUrl`，无订单、锁座、乘机人或支付 |

例如 HKG→HND 2026-11-01 样本在加入“不坐红眼”后，渠道内可用的最低报价由 FlyAI CNY 856 / Google Flights CNY 995 变为 CNY 3243 / CNY 4624。这是**条件改变后的不同航班样本**，不是同一航班涨价。详细航段与时间见两个报告。[逐轮摘要](../reports/standalone-multiturn-summary.json) 有程序状态和约束；历史宿主协作运行保存在 `reports/01`–`04` 以供追溯。

## 工程验证、风险与下一步

31 项隔离测试通过，涵盖新版 socai 返回结构、证据引用、航段/机场/日期/舱位一致性、红眼过滤、来源失败、价格口径和超时恢复。可编辑安装及 CLI/doctor 启动通过。测试用构造数据只验证代码，不代替上述真实来源记录。

本次主要剩余风险：仅验证一个新任务和三次追问，未测多天重复稳定性；候选依赖已读帖子和有限机场词表，可能漏掉更好机会；默认只抽样日期，不能断言整个日期窗口最低；缺少历史/典型价格基线、行李费用与深圳到香港机场的交通成本，不能量化“便宜程度”；FlyAI 体验模式会失败或限量，Google Flights 也可能受配额和数据延迟影响；社交登录态需用户自己的 Chrome 持续有效。空闲时 doctor 曾短暂报告端点不可达，再次只读搜索可自动连接成功；本机复测后 status 显示 `browser_connected=true`。跨来源价格比较必须先对齐税费、行李、航班和销售条件。

早期技术 spike 曾显示 socai 未连接、SerpAPI 缺 Key，后来用户完成本机配置；随后发现 socai v0.6.1 用 `notes[].entity` / `top_comments`，修正适配器后才完成上述独立运行。旧失败记录保留在 [技术验证历史](technical-spike.md)，不能当作最新状态。
